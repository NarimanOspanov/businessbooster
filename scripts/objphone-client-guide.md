# Интеграция: очередь объектов без контакта и запись телефонов

Документ для разработчика клиентской части (плагина), которая берёт из очереди
объявления Крыши без телефона, снимает номер со страницы и записывает его
обратно. Здесь всё, что нужно для интеграции: адреса, форматы, статусы, порядок
вызовов и пограничные случаи.

Базовый адрес: `https://saudager.ai`. Все ответы — JSON, кодировка UTF-8.

## 1. Доступ

Во всех запросах передаётся ключ в query-строке: `?key=<KEY>`. Ключ выдаётся
отдельно, в код и в репозиторий не кладётся.

Без ключа или с неверным ключом любой запрос отвечает:

```
403 {"ok":false,"error":"bad_key"}
```

Если плагин работает из браузера прямо со страницы `krisha.kz`, CORS уже
настроен: `Access-Control-Allow-Origin: https://krisha.kz`, методы
`GET, POST, PUT, PATCH, OPTIONS`, заголовок `Content-Type`. Preflight
(`OPTIONS`) отвечает `204`.

## 2. Как устроена очередь

Очередь — это объявления **хозяев** (не агентств), **живые**, у которых **нет
сохранённого телефона** и которые попали в нашу базу **не раньше даты `since`**.
Сервер отдаёт их **по одному**, **самые свежие первыми**: цель — снять прямой
номер хозяина до того, как агент уговорит его спрятать объявление.

Курсор на стороне плагина вести **не нужно**. Объект сам выпадает из очереди,
когда:

- ему записали хотя бы один телефон;
- плагин сообщил финальный промах (`archived`, `not_found`);
- набралось пять промахов любого рода.

После нефинального промаха (`captcha`, `timeout`, `no_phone`, `error`) объект
ставится на паузу и на время из очереди исчезает, а потом возвращается сам.

Поэтому цикл плагина простой:

```
loop:
  item = GET /api/krisha/objphone?since=...      # один объект или null
  if item == null: подождать, повторить
  открыть item.url, попытаться получить номер
  если номер есть:   POST /api/krisha/objphone       {id, phones}
  если номера нет:   POST /api/krisha/objphone/miss  {id, reason}
```

Важно: обрабатывать **по одному** и не запускать несколько параллельных
экземпляров на одном окне `since` — иначе они будут получать один и тот же
объект, пока первый его не закроет.

## 3. Взять следующий объект

```
GET /api/krisha/objphone?key=<KEY>&since=2026-09-10
```

Параметр | Обязателен | Описание
--- | --- | ---
`key`   | да  | ключ доступа
`since` | нет | не старше этой даты по попаданию в базу, `YYYY-MM-DD`. Без неё — последние 7 дней
`deal`  | нет | по умолчанию `sale` — только продажа; `rent` — аренда; `any` — без фильтра
`prop`  | нет | по умолчанию `flat` — только квартиры; `house`, `commercial`, `land`; `any` — без фильтра
`city`  | нет | по умолчанию `almaty` — только Алматы; другой город латиницей (`astana`, `shymkent`…); `any` — все города
`lease` | нет | на сколько секунд закрепить объект за этой вкладкой, по умолчанию 240, максимум 900; `0` — не закреплять

Алиас с тем же поведением: `GET /api/krisha/objqueue`.

### Параллельные вкладки

Выданный объект **арендуется** на `lease` секунд (по умолчанию 240): пока аренда
не истекла, другие вкладки его не получат, даже если запросы пришли в одну
миллисекунду. Аренда снимается, как только по объекту сохранён номер или
отправлен промах; если вкладку закрыли, объект сам вернётся в очередь через
`lease` секунд. В ответе `leaseUntil` — до какого момента (UTC) объект закреплён,
`inWork` — сколько объектов сейчас в работе у всех вкладок. `lease=0` — только
посмотреть следующий объект, не занимая его.

Аренду можно продлить: `POST /api/krisha/objphone/lease?key=<KEY>` с телом `{"id": "1015783615"}`
(необязательно `"lease": 240` — на сколько секунд). Ответ `{"ok": true, "leaseUntil": "…"}`.
Юзерскрипт зовёт его раз в две минуты из вкладки, которая открыта в фоне и ждёт,
пока на неё переключатся: в фоновой вкладке браузер не показывает капчу и не
отдаёт номер, поэтому там скрипт ничего не нажимает.


Ответ `200`:

```json
{
  "ok": true,
  "since": "2026-09-10",
  "left": 1483,
  "waiting": 12,
  "item": {
    "id": "1015783615",
    "title": "1-комнатная квартира · 34 м² · 4/7 этаж",
    "deal": "sale",
    "prop": "flat",
    "city": "almaty",
    "seller": "owner",
    "price": 23500000,
    "posted": "2026-09-10",
    "seen": "2026-09-10T08:14:03.000Z",
    "url": "https://krisha.kz/a/show/1015783615",
    "tries": 0,
    "last": null
  }
}
```

Поле | Описание
--- | ---
`since`   | граница, по которой считали (переданная или вычисленная по умолчанию)
`left`    | сколько объектов **готовы к съёму** в окне, включая этот
`waiting` | сколько объектов в окне **стоят на паузе** после промаха и вернутся позже
`item`    | следующий объект или `null`, если готовых нет

Поля `item`:

Поле | Значения
--- | ---
`id`     | номер объявления на Крыше, строка
`title`  | заголовок объявления
`deal`   | `sale` / `rent`
`prop`   | `flat` / `house` / `commercial` / `land` / `garage` / `other`
`city`   | слаг города, например `almaty`, `astana`
`seller` | всегда `owner`: очередь только по хозяевам
`price`  | цена, тенге
`posted` | дата последнего поднятия объявления `YYYY-MM-DD`
`seen`   | когда объявление впервые попало к нам, UTC; по этому полю и идёт порядок «свежие первыми»
`url`    | страница объявления
`tries`  | сколько раз номер уже пытались снять
`last`   | чем кончилась последняя попытка (`captcha`, `timeout`, …) или `null`, если не пробовали

Когда `item` равен `null`:

- `waiting > 0` — объекты есть, но на паузе; спросить снова через несколько минут;
- `waiting == 0` — в окне всё обработано; новые объявления попадут в окно сами,
  можно опрашивать раз в несколько минут.

Ошибки: `400 {"ok":false,"error":"since: нужна дата YYYY-MM-DD"}`.

## 4. Записать телефон

```
POST /api/krisha/objphone?key=<KEY>
Content-Type: application/json

{ "id": "1015783615", "phones": ["+7 705 111 22 33"] }
```

Поле | Обязателен | Описание
--- | --- | ---
`id`     | да | номер объявления
`phones` | да | массив номеров; одно значение можно передать строкой в поле `phone`

Номер принимается в любом написании — `+7 705 111 22 33`, `87051112233`,
`7051112233` — и приводится к `7XXXXXXXXXX`. Дубликаты отбрасываются.

Семантика — **добавить**: уже сохранённые номера объекта не трогаются. Это
безопасно при повторной отправке того же номера. Как только у объекта есть хоть
один номер, он выпадает из очереди.

Ответ `200`:

```json
{ "ok": true, "id": "1015783615", "phones": ["+7 705 111 22 33"] }
```

Ошибки:

- `400 {"ok":false,"error":"нет номера объявления"}` — нет `id`;
- `400 {"ok":false,"error":"номер не разобрал"}` — ни один номер не похож на казахстанский.

### Сменить IP прокси перед следующим объектом

Перед переходом на следующее объявление плагин зовёт `POST /api/krisha/objphone/rotate?key=<KEY>`:
сервер меняет выходной IP у порта Asocks, через который ходит браузер (адрес порта, логин и
пароль прежние, Chrome перенастраивать не нужно). В теле можно передать `{"port": <id>}` — порт этого
браузера; список портов даёт `GET /api/krisha/objphone/ports?key=<KEY>`. Несколько браузеров — по порту
на каждый, иначе смена IP одним меняет адрес всем. Ответ `{"ok": true, "rotated": true}`; чаще раза
в 5 секунд — `rotated: false, throttled: true`; `error: no_proxy` — на сервере прокси не настроен,
тогда метод можно больше не звать. `GET` на тот же адрес показывает, какой это порт.

## 5. Сообщить, что номер не снялся

```
POST /api/krisha/objphone/miss?key=<KEY>
Content-Type: application/json

{ "id": "1015783615", "reason": "archived" }
```

Поле | Обязателен | Описание
--- | --- | ---
`id`     | да  | номер объявления
`reason` | нет | причина; без неё считается `error`

От причины зависит судьба объекта:

`reason` | Когда слать | Что делает сервер
--- | --- | ---
`archived`  | страница открывается, но объявление снято: пометка «Объявление может быть неактуальным», архив | из очереди **насовсем**
`not_found` | страницы нет: Крыша отвечает 404, «Страница не найдена», «ссылка не существует или объявление удалено» | из очереди **насовсем**
`captcha`   | показалась капча, и её не решили за минуту и после двух перезагрузок страницы | пауза 30 минут, потом объект вернётся
`timeout`   | кнопка «Показать телефон» нажата, а номер за отведённое время не появился | пауза 1 час
`no_phone`  | страница живая, но кнопки с номером нет (например, только чат) | пауза 24 часа
`error`     | всё остальное: сеть, неожиданная вёрстка | пауза 1 час

Правила:

- пауза растёт с каждым промахом: вторая попытка ждёт вдвое дольше, третья втрое;
- каждый промах увеличивает счётчик `tries`; после **пяти** объект уходит насовсем при любой причине;
- неизвестный `reason` даёт `400` со списком допустимых значений.

Ответ `200`:

```json
{
  "ok": true,
  "id": "1015783615",
  "state": "captcha",
  "tries": 2,
  "final": false,
  "next_at": "2026-09-17T13:40:00.000Z"
}
```

Поле | Описание
--- | ---
`state`   | записанная причина
`tries`   | сколько попыток стало
`final`   | `true`, если объект больше не вернётся в очередь
`next_at` | когда объект снова станет доступен (UTC, ISO 8601); `null`, если `final`

Ошибки: `400` без `id`, `400` при неизвестном `reason`, `405` для любого метода
кроме `POST`.

## 6. Посмотреть и поправить номера объекта

Обычно не нужно в цикле плагина, но есть для ручной правки.

Что уже сохранено:

```
GET /api/krisha/objphone?key=<KEY>&id=1015783615
```

```json
{ "ok": true, "id": "1015783615", "phones": ["+7 705 111 22 33"], "raw": ["77051112233"] }
```

`phones` — в читаемом виде, `raw` — цифрами `7XXXXXXXXXX`. Если номеров нет,
оба массива пустые, `ok` всё равно `true`.

Заменить целиком (единственный способ исправить ошибочный номер):

```
PUT /api/krisha/objphone?key=<KEY>
Content-Type: application/json

{ "id": "1015783615", "phones": ["+7 701 000 00 00"] }
```

`PATCH` работает так же. Пустой массив `[]` стирает все номера и **возвращает
объект в очередь**. Если поля `phones`/`phone` в теле нет совсем — это ошибка
`400 {"ok":false,"error":"нужен список phones (может быть пустым)"}`, а не
очистка.

## 7. Что хранится на сервере

Три поля у каждого объекта, на случай если понадобятся в отчётах:

Поле | Значение
--- | ---
`phone_tries`   | сколько раз пытались снять номер
`phone_state`   | итог последней попытки: `ok` / `archived` / `not_found` / `captcha` / `timeout` / `no_phone` / `error`; `NULL` — не пробовали
`phone_next_at` | раньше этого времени объект в очередь не отдаётся

Успешная запись номера ставит `ok` и снимает паузу.

## 8. Пример на JavaScript

```js
const API = "https://saudager.ai";
const KEY = process.env.KEY;           // выдаётся отдельно
const SINCE = "2026-09-10";            // или не передавать: последняя неделя

async function call(path, method, body) {
  const sep = path.includes("?") ? "&" : "?";
  const r = await fetch(API + path + sep + "key=" + encodeURIComponent(KEY), {
    method: method || "GET",
    headers: body ? { "Content-Type": "application/json" } : undefined,
    body: body ? JSON.stringify(body) : undefined,
  });
  return r.json();
}

async function step() {
  const q = await call("/api/krisha/objphone?since=" + SINCE);
  if (!q.ok) throw new Error(q.error);
  if (!q.item) return { idle: true, waiting: q.waiting };

  const { id, url } = q.item;
  const result = await grabPhone(url);   // ваша логика: открыть страницу, снять номер
  // result: { phones: [...] } либо { reason: "archived" | "not_found" | "captcha" | "timeout" | "no_phone" | "error" }

  if (result.phones && result.phones.length) {
    return call("/api/krisha/objphone", "POST", { id, phones: result.phones });
  }
  return call("/api/krisha/objphone/miss", "POST", { id, reason: result.reason || "error" });
}
```

## 9. Пограничные случаи

- **Тот же объект пришёл дважды.** Значит, предыдущий результат по нему не
  записался (сеть, 500). Повторите `POST` номера или `miss`; оба вызова
  идемпотентны по смыслу.
- **`500 {"ok":false,"error":"..."}`.** Временная ошибка на сервере или базе.
  Подождать и повторить тот же запрос.
- **Капча.** Сервер её не решает и не видит. Если плагин не может пройти капчу,
  шлите `miss` с `reason: "captcha"` — объект вернётся через полчаса, а Крыша
  за это время остынет. Частые капчи — сигнал снизить темп.
- **Несколько номеров на странице.** Передавайте все массивом; сервер сохранит
  каждый.
- **Номер в нестандартном формате.** Сервер принимает только казахстанские
  номера: 11 цифр с `7` или `8` в начале или 10 цифр без кода. Всё остальное
  отбрасывается; если не осталось ни одного — `400 "номер не разобрал"`.
- **Нужно пройти окно заново.** Если у части объектов стёрли номера (`PUT` с
  `[]`), они вернутся в очередь сами. Менять `since` для этого не нужно.

## 10. Сводка

Метод | URL | Что делает
--- | --- | ---
`GET`  | `/api/krisha/objphone?key=&since=` | следующий объект без номера (один или `null`)
`POST` | `/api/krisha/objphone?key=` + `{id, phones}` | записать номер (добавить)
`POST` | `/api/krisha/objphone/miss?key=` + `{id, reason}` | промах с причиной
`GET`  | `/api/krisha/objphone?key=&id=` | номера одного объекта
`PUT` / `PATCH` | `/api/krisha/objphone?key=` + `{id, phones}` | заменить номера целиком
