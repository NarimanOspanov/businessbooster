# Подключение клиники: от купленного номера до первого звонка

Почти всё делается в **кабинете агента** — `/admin/`. Командная строка нужна
ровно в одном месте: провести только что купленный номер через АТС и
ElevenLabs. Всё остальное — клиника, анкета, выдача номера, передача кабинета
владельцу — кнопками.

## Первый вход в кабинет агента

Откройте `/admin/`, войдите своим аккаунтом. Первый раз страница откажет и
покажет ваш идентификатор Clerk — впишите его в настройку `ADMIN_USER_IDS` в
Azure (App Service → Configuration → Application settings), сохраните,
дождитесь перезапуска. Несколько агентов — через запятую.

Список специально не хранится в коде: агента нужно уметь и добавить, и убрать,
не выкладывая сайт заново.

## 1. Номер в Zadarma

Купили виртуальный номер — на странице заказа оставьте **«Через виртуальную
АТС»** и сохраните. Два других варианта (SIP-программа, переадресация на
телефон) ведут мимо нашей схемы.

## 2. Провести номер в работу

```bash
node scripts/provision-number.js --number=+7727XXXXXXX --free
```

Скрипт заводит **отдельный** внутренний номер АТС (занятые другими номерами он
обходит — на одном внутреннем два номера жить не могут, иначе звонки уедут
чужой клинике), ставит на него переадресацию на SIP ElevenLabs, импортирует
номер в ElevenLabs и кладёт в пул. Падение на середине не страшно: запускается
повторно.

`--free` значит «номер активирован у оператора и готов к выдаче». Если ещё нет
— запускайте без флага, номер ляжет как `preparing` и в кабинете будет виден,
но недоступен для выдачи.

Что нужно скрипту: ключ и секрет API Zadarma в `~/.zadarma-keys` (две строки),
ключ ElevenLabs в `~/.elevenlabs-key`, строка подключения к базе в
`~/.azure-sql-connection`. В переписке ключи не пересылаем.

### И один шаг руками — без него номера перепутаются

**В панели Zadarma**: «Моя АТС» → входящие звонки этого номера направить на
тот внутренний, который назвал скрипт.

Почему без этого нельзя. В АТС сценарий входящих по умолчанию один на всю
станцию: звонок на *любой* номер звонит сразу на все внутренние. А
переадресация на SIP ElevenLabs настраивается на внутреннем и ведёт на
конкретный номер — то есть на конкретного агента. Пока у номеров нет своих
сценариев, звонок пациента одной клиники может поднять ассистент другой:
кто из внутренних ответил первым, тот и говорит.

Через API этого не сделать: метод `/v1/pbx/ivr/scenario/create/` на наших
ключах отвечает «Not authorized», хотя чтение сценариев работает. Пробовали —
не вышло; если Zadarma когда-нибудь откроет метод, шаг уедет в провизионер.

Проверить, что получилось, можно не заходя в панель:

```bash
node -e "require('./scripts/zadarma').call('/v1/pbx/ivr/scenario/').then(r=>console.log(JSON.stringify(r,null,1)))"
```

У каждого номера должен быть свой сценарий со своим внутренним.

## 3. Клиника — в кабинете агента

`/admin/` → поле «Название новой клиники» → **Создать**. Заводится организация
в Clerk и клиника под ней. Кабинет пока ваш: у клиники ещё нет входа.

Своим аккаунтом мастер `/start/` для клиента **не заполняем** — там одна
клиника на организацию, и он перезапишет вашу демо-клинику.

## 4. Номер — клинике

В карточке клиники раздел «Номер»: выбрать из свободных → **Привязать**.
Если ассистент уже собран, номер сразу начнёт отвечать её голосом; если нет —
привяжется к агенту при включении.

«Открепить» возвращает номер в пул и переводит его обратно на демо-агента,
чтобы освобождённый номер не отвечал голосом бывшего клиента.

## 5. Анкета

«Откуда взять данные»: ссылка на 2GIS, сайт, Instagram → **Подтянуть из
ссылок**. Заполнятся только пустые поля — то, что вы вписали руками, не
затирается.

Что проверить перед включением:

- **Услуги и цены.** Чего нет в этом поле — ассистент не назовёт. Главное поле.
- **Часы работы** — по ним он говорит, когда клиника открыта.
- **Как записывать** — подтверждать время сразу или обещать звонок
  администратора.
- **Что делать при острой боли** — куда направлять ночью.

**Включить ассистента** — собирает агента по анкете и ставит его на номер.
Дальше эта же кнопка называется «Обновить ассистента»: правки анкеты попадают
в работу только после неё.

## 6. Переадресация со своего номера клиники

Клиника набирает на телефоне, куда сейчас звонят пациенты:

- `**61*+7727XXXXXXX**25#` — если не ответили за 25 секунд (шесть гудков);
- `**62*+7727XXXXXXX#` — если телефон вне зоны;
- `**67*+7727XXXXXXX#` — если занято.

Проверить: `*#61#`. Снять всё: `#002#`. На iPhone коды не проходят при
включённом Wi-Fi Calling — сначала выключить.

## 7. Проверка и передача

1. Позвонить на новый номер, поговорить с ассистентом.
2. Открыть кабинет — запись, расшифровка и карточка звонка должны появиться.
3. Проверить уведомление в Telegram.
4. Позвонить на номер клиники и не брать трубку — звонок должен уйти
   ассистенту через переадресацию.
5. «Передать кабинет клинике»: почта владельца → **Пригласить**. Ему придёт
   письмо со ссылкой на вход, после этого он видит свои звонки сам.

Если в кабинете пусто, а звонок был: почти всегда номер в ElevenLabs остался на
старом агенте. Видно в `node scripts/assign-number.js --list` — там же лежит
запасной путь для той же работы из командной строки.
