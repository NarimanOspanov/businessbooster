# API: телефоны объектов (новая архитектура, krisha_objects)

Один эндпоинт, домен `https://saudager.ai`, поведение зависит от HTTP-метода.
Это аналог `/api/krisha/phone`, но для таблицы `krisha_objects` — весь поток
недвижимости (квартиры, дома, участки, коммерция; продажа и аренда).
Телефоны хранятся колонкой в самой таблице объектов.

Ключ доступа — тот же, что у остального Krisha-API, передаётся в query-строке.

```
KRISHA_PHONE_KEY = <значение из ~/.krisha-creds на сервере>
```

Без верного `key` любой запрос отвечает `403 {"ok":false,"error":"bad_key"}`.
Адрес `https://saudager.ai/api/krisha/objqueue` — алиас на `GET` без `id`
(тот же режим «следующий без номера»).

## Как это работает с плагином

Плагин обрабатывает объекты **по одному**: спрашивает «кого дальше», открывает
страницу, снимает номер, сохраняет — и снова спрашивает. Курсор на стороне
плагина вести не нужно: как только у объекта появился номер (или пять
промахов), он сам выпадает из очереди, и следующий вызов отдаёт следующий.

Очередь — объекты без сохранённого номера, опубликованные **не раньше `since`**,
в порядке от старых к новым (от границы вверх, к сегодняшнему дню).

Цикл плагина:

1. `GET /api/krisha/objphone?key=&since=2026-09-10` → один объект или `null`.
2. Открыть `item.url`, получить номер.
3. Номер есть → `POST /api/krisha/objphone` с `id` и `phones`.
   Номера нет (объявление снято, кнопки нет) → `POST /api/krisha/objphone/miss` с `id`.
4. Снова шаг 1.

Если `item` пришёл `null` — в окне от `since` всё обработано; можно подождать
и спросить снова: новые объявления попадут в окно сами.

## GET — следующий объект без сохранённого номера

```
GET https://saudager.ai/api/krisha/objphone?key=<KEY>&since=2026-09-10
```

Параметр | Обязателен | Описание
--- | --- | ---
`key`   | да  | ключ доступа
`since` | нет | нижняя граница по дате публикации, `YYYY-MM-DD`; без неё — последние 7 дней

Ответ 200:

```
{
  "ok": true,
  "since": "2026-09-10",
  "left": 1483,
  "item": {
    "id": "1015783615",
    "title": "1-комнатная квартира · 34 м² · 4/7 этаж",
    "deal": "sale", "prop": "flat", "city": "almaty",
    "seller": "owner",
    "posted": "2026-09-10",
    "url": "https://krisha.kz/a/show/1015783615"
  }
}
```

`since` — граница, по которой считали (та, что передана, или вычисленная по умолчанию).
`left` — сколько объектов без номера осталось в окне от `since`, включая этот.
`item` — следующий объект: id, заголовок, сделка, тип, город, кто продаёт
(`owner` / `agent` / `specialist` / `company` / `complex`), дата публикации,
ссылка. Если в окне никого нет — `"item": null`, `ok` всё равно `true`.

Ошибки:
- `400 {"ok":false,"error":"since: нужна дата YYYY-MM-DD"}` — `since` не разобран.

## POST /miss — номер на странице не нашёлся

```
POST https://saudager.ai/api/krisha/objphone/miss?key=<KEY>
Content-Type: application/json

{ "id": "1015783615" }
```

Плагин зовёт это, когда на странице нет ни кнопки «Показать телефон», ни
самого номера — похоже, объявление снято. Промах считается; после **пяти**
промахов объект перестаёт попадать в очередь `GET`. Без этого первое же
снятое объявление в окне возвращалось бы плагину бесконечно.

Ответ 200: `{ "ok": true, "id": "1015783615" }`.
Только `POST`; иначе `405`.

## GET — что уже сохранено по одному объекту

```
GET https://saudager.ai/api/krisha/objphone?key=<KEY>&id=1015783615
```

Параметр | Обязателен | Описание
--- | --- | ---
`key` | да | ключ доступа
`id`  | да | номер объявления на Крыше

Ответ 200:

```
{
  "ok": true,
  "id": "1015783615",
  "phones": ["+7 705 111 22 33"],
  "raw": ["77051112233"]
}
```

`phones` — номера в читаемом виде.
`raw` — те же номера цифрами, `7XXXXXXXXXX` (11 цифр, без `+`).
Если номеров нет — оба массива пустые, `ok` всё равно `true`.
Смотреть перед правкой — чтобы не перезаписать номер вслепую.

## POST — сохранить номер (добавить к тому, что уже есть)

```
POST https://saudager.ai/api/krisha/objphone?key=<KEY>
Content-Type: application/json

{ "id": "1015783615", "phones": ["+7 705 111 22 33"] }
```

Поле тела | Обязателен | Описание
--- | --- | ---
`id`     | да | номер объявления
`phones` | да | массив номеров (можно и одно строкой в `phone`)

Номер разбирается из любого написания: `+7 705 111 22 33`, `87051112233`,
`7051112233` — итог всегда `7XXXXXXXXXX`.
Ведёт себя как «добавить», не «заменить»: старые номера этого объекта не
трогает, только дописывает новые. Как только у объекта есть хоть один номер —
он выпадает из очереди `GET`.

Ответ 200:

```
{ "ok": true, "id": "1015783615", "phones": ["+7 705 111 22 33"] }
```

Ошибки:
- `400 {"ok":false,"error":"нет номера объявления"}` — не передан `id`.
- `400 {"ok":false,"error":"номер не разобрал"}` — в `phones` нет ни одного
  валидного номера.

## PUT / PATCH — заменить номера целиком

```
PUT https://saudager.ai/api/krisha/objphone?key=<KEY>
Content-Type: application/json

{ "id": "1015783615", "phones": ["+7 701 000 00 00"] }
```

То же тело, что у `POST`, но стирает все прежние номера объекта и записывает
только переданные. Единственный способ поправить ошибочный номер (`POST`
только добавляет). Пустой список — осознанная очистка (вернёт объект в очередь):

```
{ "id": "1015783615", "phones": [] }
```

Если поле `phones`/`phone` в теле вообще отсутствует — это ошибка запроса, а не
очистка:

```
400 {"ok":false,"error":"нужен список phones (может быть пустым)"}
```

`PATCH` работает идентично `PUT`.

Ответ 200:

```
{ "ok": true, "id": "1015783615", "phones": ["+7 701 000 00 00"] }
```

## CORS

Эндпоинт вызывается напрямую со страницы `krisha.kz` (браузерным плагином):

```
Access-Control-Allow-Origin: https://krisha.kz
Access-Control-Allow-Methods: GET, POST, PUT, PATCH, OPTIONS
Access-Control-Allow-Headers: Content-Type
```

`OPTIONS`-запрос (preflight) отвечает `204` без тела.

## Сводка

Метод | URL | Что делает
--- | --- | ---
`GET` | `/api/krisha/objphone?key=&since=` | следующий объект без номера (один или `null`)
`GET` | `/api/krisha/objphone?key=&id=` | номера одного объекта
`POST` | `/api/krisha/objphone?key=` + body | добавить номер
`PUT` / `PATCH` | `/api/krisha/objphone?key=` + body | заменить номера целиком
`POST` | `/api/krisha/objphone/miss?key=` + body | промах: номера на странице нет
