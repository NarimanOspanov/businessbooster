# Open-source движки магазинов для Saudaget — ресёрч (август 2026)

Вопрос: можно ли взять исходники Shopify или open-source аналог, чтобы «по щелчку» разворачивать полноценный магазин каждому селлеру. Проверено по GitHub-репозиториям и лицензиям на 2026-08.

## 1. GitHub Shopify — что реально открыто

**Ядро Shopify (движок, чекаут, заказы, админка) никогда не публиковалось — воспользоваться «исходниками Shopify» нельзя.** Их опенсорс — это инструменты вокруг платной платформы:

| Проект | Лицензия | Можно ли использовать отдельно от Shopify |
|---|---|---|
| Hydrogen (React-фреймворк витрин) | MIT | Юридически да, практически нет — весь слой данных завязан на платный Storefront API |
| Dawn (эталонная тема) | Кастомная: «только для интеграции с Shopify» | **Нет — прямо запрещено** |
| Polaris (дизайн-система админки) | Кастомная MIT-подобная с ограничением «для Shopify» | Нет |
| **Liquid (шаблонизатор)** | **MIT** | **Да!** Для Node — независимый порт **LiquidJS** (MIT). Единственная по-настоящему полезная нам деталь: безопасные шаблоны, редактируемые мерчантом |

## 2. Open-source движки: главное

| Движок | Лицензия | Стек | Мультитенантность (1 деплой → много магазинов со своими доменами) | Вердикт |
|---|---|---|---|---|
| **Medusa** ⭐ | **MIT** ✅ | Node/TS/Postgres, ~35.6k★ | Частичная: Sales Channels + Store per merchant, жёсткая изоляция — DIY (RLS) | **Наш выбор для фазы C**: наш стек, чистая лицензия, официальный Stripe-модуль, кастомные провайдеры для Kaspi Pay, всё создаётся по API |
| Vendure | GPL-3.0 ⚠ | Node/NestJS | **Лучшая**: каналы спроектированы под мультитенант, свои платёжки на канал | Технически идеален, но GPL для закрытого SaaS = ограничения (или платная лицензия) |
| Saleor | BSD-3 ✅ | Python | Каналы = рынки одной компании, не независимые мерчанты | Чужой стек + не наша модель |
| WooCommerce + WP Multisite | GPL-3.0 | PHP | Да, доказано на тысячах магазинов (Ultimate Multisite) | Работает, но PHP-монолит × 1000 сайтов = операционная каторга, ломает наш стек |
| PrestaShop | OSL-3.0 ⚠ | PHP | Да (multistore) | Лицензия квази-AGPL для SaaS — мимо |
| Spree | ядро BSD-3, **multi_store — AGPL/платно** ⚠ | Ruby | Ровно нужный модуль — под AGPL | Мимо |
| OpenCart / Unchained / прочие | GPL / EUPL / малые комьюнити | — | — | Мимо |

**Лицензии, важное**: AGPL и OSL для закрытого SaaS = обязанность открыть код — избегаем. Обычный GPL (Vendure, Woo) для SaaS допустим (сетевое использование ≠ распространение), но осложняет будущее (M&A due diligence, on-prem). Чисто: MIT (Medusa), BSD-3 (Saleor, Solidus).

## 3. Вердикт по фазам

- **Фаза A (сейчас — каталоги + кнопки на маркетплейс): движок НЕ нужен.** Ни один опенсорс не делает мультитенантные SSR-витрины лучше нашего собственного генератора (это ровно та часть, которую Shopify не открыл). Взять: **LiquidJS** (шаблоны, настраиваемые мерчантом), vercel/commerce как референс SSR/SEO-архитектуры, **Cloudflare for SaaS** для кастомных доменов (~$0.10/домен/мес).
- **Фаза B (прямой чекаут): движок всё ещё не нужен.** Stripe Checkout — редирект; Kaspi Pay — тонкий REST (счёт + вебхук; мерчанту нужен свой договор Kaspi как юрлицу КЗ). Таблица заказов + вебхуки в нашем же Node-приложении.
- **Фаза C (корзины, склад, fulfilment на тысячи селлеров): один общий инстанс Medusa** за нашим SSR-фронтом; мерчант = sales channel + store record + свой publishable key. Триггер перехода: многотоварные корзины и складской учёт.

**Экономика на 1 000 мерчантов/мес**: наш генератор + CDN ≈ $150–500; общий Medusa ≈ $600–2 000; инстанс-на-мерчанта ≈ $15–30k (не вариант); WP Multisite ≈ дёшево по железу, дорого по людям.

**Одной строкой**: свой SSR-генератор остаётся навсегда как витринный слой (+LiquidJS), чекаут прикручиваем напрямую (Stripe/Kaspi Pay), Medusa подключаем одним общим инстансом, когда появятся настоящие заказы и склад. Из репозиториев Shopify берём только Liquid — всё остальное закрыто лицензией или архитектурой.
