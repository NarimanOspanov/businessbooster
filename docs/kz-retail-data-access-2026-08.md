## Ключевые находки

### 1. ForteMarket — лучший необнаруженный API в стране

```
POST https://apigw.forte.kz/fm/api/v4/products/showcase/filter-lite
{"from":0,"size":10,"category":"","product_ids":[],"city":"KZ","query":"iphone"}
→ {"total_hits":13766,"products":[...]}
```

Без авторизации, без антибота, 10/10 успешных запросов подряд. Отдаёт: цену, старую цену, скидку, **наличие**, характеристики, картинки, рейтинг, отзывы, габариты. Это полноценный конкурентный фид цен и остатков.

**На GitHub — ноль репозиториев по market.forte.kz.** Никто этого не заметил.

### 2. Wildberries — я ошибся, карточки доступны

Предыдущий вывод «WB закрыт полностью» **неверен**. Закрыт только поиск:

- ✅ **Работает**: `https://card.wb.ru/cards/v4/detail?appType=1&curr=kzt&dest=234&spp=30&nm=<id>` → 200 JSON, без авторизации, пакетами до 60 товаров, без лимитов (20 запросов подряд — все 200).
- **dest=234 — это Казахстан** (подтверждено через их geo-API по координатам Алматы). Регион реально меняет ответ: цены и логистика для KZ отличаются от московских.
- ✅ Статические карточки: `basket-NN.wbbasket.ru/vol{V}/part{P}/{nm}/info/ru/card.json`, номер шарда = функция от `nm/100000`.
- ❌ Заблокировано: `search.wb.ru` (429 на всех попытках), `catalog.wb.ru` (403), витрина (498, челлендж wbaas).

**Вывод**: если знать ID товаров — данные WB для Казахстана берутся свободно. Проблема не в данных, а в **обнаружении** товаров продавца.

### 3. Evrika — всё в HTML

Next.js SSR: в `__NEXT_DATA__` лежит готовый `jsonLd` с `@type: Product`, ценой, брендом, SKU, плюс 93 КБ кэша React Query с полным описанием. Цены привязаны к городу, sitemap разбит по городам и **свежий** (lastmod того же дня).

### 4. Kaspi: XML входящий, и это подарок

Kaspi не публикует фид — наоборот, **продавцы отдают ему XML**, который Kaspi забирает каждые 60 минут. Значит у каждого активного мерчанта уже есть публичный URL с его каталогом, ценами и остатками.

**Лучший онбординг-вопрос в нашем продукте: «дайте ту же ссылку, что вы дали Kaspi».** Ноль работы для продавца, а мы получаем настоящие данные вместо парсинга выдачи.

### 5. Kaspi отдаёт цены ВСЕХ продавцов по товару — главная находка

```
POST https://kaspi.kz/yml/offer-view/offers/{sku}
{"cityId":"750000000","id":"<sku>","merchantUID":"","limit":5,"page":0,
 "sort":true,"installationId":"-1","zoneId":["Magnum_ZONE1"]}
```

Возвращает массив `offers[]`: **merchantId, merchantName, цена, рейтинг продавца, количество отзывов**, даты доставки и самовывоза. Проверено вживую — 13 КБ реальных данных по одному SKU.

Это ровно тот примитив, на котором строятся репрайсеры. **Ни один поддерживаемый open-source проект его не использует.**

Плюс каталожный эндпоинт `GET /yml/product-view/pl/filters?q=:category:smartphones:...&c=750000000` — карточки с ценой, ценой с бонусами, рейтингом, остатком и лучшим продавцом.

⚠️ Каталожный маршрут отдаёт **403 датацентровому клиенту** при том, что в браузере работает — защита выборочная, по маршруту (Referer/UA/репутация IP), а не общий WAF. Наш ингест это уже обходит.

### 6. Technodom — самая лёгкая цель из всех

```
GET https://api.technodom.kz/katalog/api/v2/products/category/{categoryCode}?city_id=5f5f1e3b4c8a49e692fefd70&limit=100
```

Без авторизации, **без единого заголовка**, антибот не обнаружен вообще, работает с датацентрового IP. Отдаёт: `sku`, `title`, `price`, `old_price`, `discount`, `brand`, `rating`, `reviews`, категории, картинки, стикеры.

Второй путь: `https://www.technodom.kz/_next/data/{buildId}/almaty/catalog/{slug}.json` — 326 КБ JSON со списком товаров.

**Alser**: `POST https://alser.kz/api/v2/mobapi-v3-get-catalog` с телом `{"c_keyword":"smartfony","page":1,"limit":12,"location_id":8}` — работает с датацентра (Cloudflare-челлендж развёрнут, но в пассивном режиме — это хрупко, могут включить одним тумблером). В robots.txt при этом `Disallow: /api/`.

**Sulpak**: JSON-API нет, но сайт полностью серверный — все 88 товаров категории лежат в HTML, парсится BeautifulSoup. Селекторы из репозитория 2022 года **до сих пор валидны**.

**Mechta**: API чистейший (`/api/v3/catalog/products?slug=`), но Cloudflare JS Detection **активно блокирует** — 403 на всё с датацентра. Нужен реальный браузер или CF-solving прокси.

### 7. Экосистемы парсеров не существует

По всем пяти сетям максимум звёзд на GitHub у любого скрейпера — **2**. Ничего не поддерживается, большинство репозиториев 2022–2023 годов и уже сломано. Про `market.forte.kz` и `evrika.com` — **ноль репозиториев вообще**, при том что у Forte API нараспашку.

То есть техническое знание, которое мы сейчас собрали, в открытом доступе отсутствует.

### 8. Крупные сети не кормят агрегаторов

Technodom, Sulpak, Mechta, Alser, Evrika фидов не публикуют. И показательно: **e-katalog.kz работает в РК годами с 3 000+ магазинов и этих сетей тоже не подключил** — на их странице iPhone 16 тринадцать предложений, все от мелких магазинов. Предположение «большие уже отдают данные агрегаторам» в Казахстане не выполняется.

Два нюанса:
- **Mechta** отвечает 403 (а не 404) на путях Bitrix-экспорта — фид, возможно, есть за файрволом. Проверить с казахстанского IP.
- **alser.kz** объявил в robots.txt `ai-train=yes, search=yes, ai-input=yes` — редкая открытость к ИИ, хороший заход для партнёрства.

## Что из этого следует для нас

1. **Ингест Kaspi можно улучшить сразу** — просить у продавца его XML-ссылку вместо парсинга поиска.
2. **ForteMarket и Evrika — самые дешёвые новые источники**, если решим расширять покрытие.
3. **Wildberries реалистичен** при решённой задаче обнаружения товаров (например, через sitemap или карточки, найденные в поиске с резидентного IP).
4. **Ozon требует настоящего браузера** — Apify или headless, отдельная стоимость.
